DDL names objects and rules. The local lab does **not** run `CREATE` / `ALTER` / `DROP` — copy these into a warehouse. This cluster is the exercise-map for databases, tables, constraints, indexes, and identity columns.

## Databases: create, drop, backup

```sql
-- Dialect: illustrative admin SQL
CREATE DATABASE analytics_scratch;
DROP DATABASE analytics_scratch;
```

“Backup database” is platform-shaped:

- **Postgres / SQL Server** — dump or `BACKUP DATABASE` to a file/URL.
- **Snowflake** — Time Travel + `CREATE DATABASE … CLONE` (zero-copy) more often than a nightly dump.
- **Databricks** — clone / deep clone a Delta table, not a server-level backup verb.

Never `DROP DATABASE` in prod without a restore story.

## Tables: create, alter, drop

```sql
CREATE TABLE lab_loyalty (
  loyalty_id INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL UNIQUE,
  points INTEGER NOT NULL DEFAULT 0,
  tier TEXT NOT NULL CHECK (tier IN ('bronze', 'silver', 'gold')),
  FOREIGN KEY (customer_id) REFERENCES lab_customers (customer_id)
);

ALTER TABLE lab_loyalty ADD COLUMN enrolled_on DATE;
DROP TABLE lab_loyalty;
```

`ALTER` also `DROP COLUMN`, `RENAME`, or `ALTER COLUMN … SET NOT NULL` depending on the dialect.

## Constraint menu

| Constraint | Promise |
|------------|---------|
| `NOT NULL` | Writes must supply a value |
| `UNIQUE` | No duplicate (NULLs are dialect-specific) |
| `PRIMARY KEY` | Unique + not null identity |
| `FOREIGN KEY` | Values exist on the parent (or NULL if allowed) |
| `CHECK` | Row predicate (`points >= 0`) |
| `DEFAULT` | Fill when the insert omits the column |

Name constraints (`CONSTRAINT fk_loyalty_customer`) so error messages are readable.

## Index and auto increment

```sql
CREATE INDEX idx_loyalty_tier ON lab_loyalty (tier);
```

Indexes help `WHERE` / `JOIN` / `ORDER BY` on that key. They slow writes. Do not index every column.

Identity / auto increment (dialect clothes):

```sql
-- SQL Server / Azure
loyalty_id INT IDENTITY(1,1) PRIMARY KEY
-- Postgres
loyalty_id INTEGER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY
-- MySQL
loyalty_id INT AUTO_INCREMENT PRIMARY KEY
```

Warehouses often use `IDENTITY` or a sequence. Do not assume gaps will never appear after a failed load.
